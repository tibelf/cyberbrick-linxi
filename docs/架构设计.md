# CyberBrick 语音坦克 — 架构设计

一辆能发射子弹的 CyberBrick Mini T 履带车，接入灵矽（Linx）平台：用户直接对它说话，它听懂后照做，并用语音回应。

没有灵矽实体硬件，所以由电脑上的 `linx-client` **模拟一台灵矽设备**（用电脑的麦克风和扬声器），再通过 Wi-Fi 或 USB 控车。

## 1. 主打场景

| 场景 | 内容 | 用户怎么说 | 实现 |
|---|---|---|---|
| 1 | 发射炮弹 | “开一炮” | MCP 工具 `self.tank.fire`：扣扳机舵机发射，每次最多 3 发，间隔 1.5 秒冷却 |
| 1 | 绕杯子一圈 | “拍一张俯拍图”→“绕着杯子转一圈” | 闭眼导航 `self.blind.goto(where=绕一圈)`：拍一张俯拍图规划路线，之后不再拍照，按校准参数走完并回到出发点 |
| 2 | 跳舞 | “跳个舞” | `self.tank.dance`：原地左右扭两下，炮管上下点头 |
| 3 | 录制动作宏（语音编程） | 边做边学：“开始学动作”→ 照常下令 →“记住这套叫全军出击”；或一句话定义：“记住，全军出击就是全速前进 5 秒”。之后说“执行全军出击” | `self.macro.*`：录制时 executor 把用户下令的动作按固定写法记下来，存成有名字的宏（本机 `.macros.json`）。执行时作为任务跑，每步仍受安全约束，一次最多 60 秒，“停”随时打断。演示示例「全军出击」=`前进 5000 速度 100` |
| 4 | 闲逛（全屋探索） | “自己逛逛”“随便走走” | `self.tank.wander`：随机挑方向和距离（每段 1.2–2.5 秒），有摄像头时边走边看、前方堵住就转向；没有摄像头时慢速闭眼逛。只有说“停”才结束，闲逛绝不开火 |
| 5 | 老爷爷模式 | “切换成老爷爷模式” | 人格 `grandpa`：速度不超过 65，每走 0.3 秒歇 0.15 秒；说话慢悠悠、爱唠叨 |

**老爷爷模式是“人格”，和闲逛这类“任务”是两回事。** 人格改变的是**怎么走、怎么说话**，对每一个前进/后退指令都生效，一直保持到用户说“恢复正常”；闲逛是**去哪里**的任务。两者可以叠加：老爷爷模式下让它闲逛，就是走走停停地逛。

## 2. 总体架构

![CyberBrick 语音坦克总体架构](images/architecture.png)

用户的语音经电脑上的 `linx-client` 上传到灵矽平台；平台识别、理解后用 MCP 调用小车工具。语音指令、闲逛等长任务、网页和手机手柄的操作，全部汇入动作队列做安全检查，再经 Wi-Fi UDP（或 USB）发给车上的 Core，由它驱动履带、炮管和扳机。

三层职责严格分开：

| 层 | 负责 | 不负责 |
|---|---|---|
| 灵矽平台 | 听懂（ASR）、理解并拆解成工具调用（大模型 Function Call）、说话（TTS） | 动作时长、安全 |
| linx-client | 排程、人格、长任务（闲逛/导航/宏）、安全约束、网页控制台 | 语音识别 |
| 车上 Core | 执行单条指令、看门狗兜底停车 | 计时、排程 |

## 3. 模块规格

### 3.1 灵矽平台接入

- **`ota.py` / `identity.py`**：首次运行生成虚拟 MAC，上报 OTA 拿到 6 位激活码，到智控台绑定。身份存在 `.linx_device.json`（不进仓库）。
- **`session.py`**：WebSocket 会话。握手头带 `Authorization`、`Device-Id`、`Client-Id`、`Protocol-Version`。上行 PCM 16kHz / 20ms 帧；下行格式以服务端 hello 为准。默认半双工（小车说话时不上传麦克风），`--duplex` 时用回声估计判断用户插话。断线指数退避重连。
- **`mcp.py`**：设备端 MCP 服务，平台是客户端。消息封装为 `{"type":"mcp","payload":<JSON-RPC>}`。参数只用 integer / string / boolean，整数自动裁剪到 min/max。工具出错一律转成 `isError` 结果，不断开连接。
- **`tools.py`**：工具名、描述、参数。描述文字直接决定大模型何时调用，比如开火只在用户明确要求时调用。
- **`prompts/agent-prompt.md`**：粘贴到智控台的角色提示词，规定人格说话风格、什么时候调用哪个工具。

### 3.2 动作执行与安全（`tank/executor.py`）

- 工具调用**立即返回“已安排”**，动作进入队列由后台顺序执行，所以“前进两秒然后开一炮”会被大模型拆成两次调用、自然串成序列。
- 安全约束集中在这里，任何功能都不能绕过：

  | 约束 | 值 |
  |---|---|
  | 单个动作时长 | ≤ 5 秒 |
  | 队列总时长 | ≤ 15 秒（超出直接拒绝） |
  | 速度 | 裁剪到 `--max-speed` |
  | 发射 | 每次 ≤ 3 发，间隔 1.5 秒冷却；`--no-fire` 整体锁定 |
  | 原地转向 | 超过 90° 拆成几段，段间停 0.3 秒（转太久会越转越快） |

- **急停**（语音“停”、终端回车、网页急停按钮、键盘 Esc）不进队列：清空队列、取消当前动作和任务、立即停车。
- **人格**在 `move()` 里生效：老爷爷模式限速 65、每走 0.3 秒歇 0.15 秒。闭眼导航时临时按正常模式走，因为走走停停会让按时间换算的距离不准。
- **时长由电脑控制，车只设状态**：`drive(left, right, failsafe_ms)` 只设输出并启动车上看门狗，电脑 sleep 到点后发停车。`failsafe_ms = 时长 + 300ms`，电脑崩溃或断网时车会自己停。
- 后台出错记进 `last_error`，同时推送到网页和语音播报，不只打印在终端。空闲时每 5 秒心跳问一次车，发现车重启会报告。

### 3.3 长任务

平台每轮对话只执行一次工具调用，所以需要持续一段时间、边走边判断的功能，在本地作为“任务”运行（`TankExecutor.start_mission`）。任务里的每一步仍然走 executor 的安全约束；急停会连任务一起取消；新任务会接替正在跑的任务。

| 模块 | 工具 | 说明 |
|---|---|---|
| `wander.py` | `self.tank.wander` | 闲逛。流水线：当前段在走时就拍下一张照片分析，下一段提前排进队列。前方堵住立即刹车转向；一直没挪动就后退掉头；连续 3 次看不清就改为闭眼慢逛，后台定时重试摄像头。和平台断线时暂停，重连后继续 |
| `blind.py` | `self.blind.map` / `self.blind.goto` | 闭眼导航。拍一张俯拍图交给视觉模型，得到车、目标和障碍物的位置，规划绕开障碍物的路线，之后按校准参数（`--blind-cm-per-s` 直行速度、`--turn-ms-per-90` 转向时长）闭眼走完。`where` 支持旁边 / 后面 / 左边 / 右边 / 绕一圈 / 撞倒 |
| `macros.py` | `self.macro.save` / `run` / `list` / `delete` / `record_start` / `record_stop` | 动作宏（语音编程）。步骤是固定写法：`前进 2000 [速度 80]`、`左转 90`、`炮管压 300`、`开火 1`、`跳舞`、`等待 500`、`执行 别的宏`。最多 40 步、重复 10 次、一次最多跑 60 秒。存在 `.macros.json`（不进仓库） |
| `camera.py` | `self.camera.take_photo` | 取图（电脑摄像头 / 手机 IP Webcam 快照地址 / 文件），交给灵矽视觉接口分析 |

### 3.4 控车链路（backend）

所有 backend 实现同一个接口（`tank/backend.py` 的 `TankBackend`），executor 不关心是哪种。

| backend | 链路 | 用途 |
|---|---|---|
| `udp` | Wi-Fi，UDP 4210 发指令，`stat` 查开机时长做心跳 | 演示主用，车可以自由跑 |
| `serial` | USB 串口进 MicroPython raw REPL，一次性注入驱动代码，之后每条指令一行函数调用 | 有线调试 |
| `mock` | 只打印 | 不接车联调 |

车端程序 `firmware/car/`（`boot.py` + `wifi_main.py`）由 `python -m linx_client wifi-setup` 装到车上。网络出错只记日志继续；意外错误先停车、写 `/wifi_err.log`、再重启。

接线（来自车上原厂配置 `rc_config`）：

| 执行器 | 端口 |
|---|---|
| 履带 | MOTOR1 Pin4/5、MOTOR2 Pin6/7（反装） |
| 炮塔 | SERVO1 Pin3（连续旋转舵机，按速度 + 时长控制） |
| 发射扳机 | SERVO2 Pin2（86° 松开 / 150° 扣下） |

### 3.5 网页控制台（`web.py` + `web/`）

- `--web` 打开 `http://localhost:8080`：通讯记录（对话、工具调用、照片）、车况、急停、人格切换、手动控制、打靶计分。
- `--pad` 再开放手机手柄（局域网，地址带随机密钥，控制台上有二维码）：摇杆控两条履带，按住炮管键调角度，开火键。
- 网页和终端、语音共用同一个 executor，所以安全约束一样生效。

## 4. 关键设计取舍

- **长任务在本地跑**：平台一轮只调一次工具，“走一步看一步”的循环只能放在设备端；大模型只负责发起和转述结果。
- **安全约束只写在一个地方**：所有入口（语音、网页、手柄、宏、任务）都经过 executor，不允许直接调用 backend。
