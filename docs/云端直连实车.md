# 小车直连云端（测试版）

2026-11-01：腾讯云 `cyberbrick-cloud-demo` 已切换到实车模式，小车通过手机 2.4 GHz 热点主动连接腾讯云，手机网页负责语音和按键，现场目标是不需要电脑常驻。当前**发射锁定**，尚未接入摄像头。

独立联调中，用户确认架空的小车在接到短时前进指令后两条履带都转动；云端收到前进与停车的设备确认。正式网页在服务器上显示实车在线、灵矽已连接。用户解决手机网络问题后，已确认手机网页按住前进时两条履带转动、松手后停止。语音控实车、拔 USB 和真实断线停车仍待实测，具体进度以 [交接看板](HANDOFF.md) 最新记录为准。

## 使用与恢复

1. 打开手机 2.4 GHz 热点，打开小车电源。当前热点已保存在车上，主控开机后自动连接云端。
2. 手机打开 [腾讯云控制台](https://110.40.227.30/)，使用原来的浏览器账号密码登录，再用同一控制密码连接网页；密码不要提交仓库或发到聊天。
3. 首次测试先卸弹、架空，确认网页显示「真实小车在线」，按住方向键，松开应停车；语音需点击「启用语音」并授权麦克风。当前速度上限为 40，履带落地后能否带动车尚未验证。
4. 若要回原厂遥控，在开机时按住主控板的 Pin 9 板载按键。云端模式不启动原 Wi-Fi UDP 及维护接口；需要改车端配置或卸载时通过 USB 维护。安装前的启动文件备份在车端 `/boot.pre-cloud-20261101.py`；`wifi-setup --uninstall` 通过 USB 恢复原厂并删除云端配置。

## 实现和约束

- 网页与云端服务走 HTTPS/WSS，用户连接需原有网页登录及控制密码；灵矽虚拟设备仍运行在腾讯云。火山云使用同一灵矽身份，不能同时启动。
- 车主动通过 WSS 连接 Nginx 的设备入口，服务器应用仅监听回环地址；车上使用私有 CA、`CERT_REQUIRED` 和服务名校验，并使用独立随机设备口令认证。设备证书有效性需要校时，当前小车通过 NTP 同步时间。实测正确证书通过，错误 CA 和错误服务名被拒绝。
- `cloud_car.py` 只在设备轮询时下发动作；服务端丢弃排队超过 400 ms 的指令，车端拒绝轮询往返超过 800 ms 的动作并检查编号与参数。断线时车端尝试停车，电机由硬件看门狗兜底；断线和弱网情况下的实际停车效果仍待实车验证。
- 云端 `TankExecutor` 保留队列、时长和限速约束；手机页面使用定期租约确认控制者在线。云端和车端均锁定发射，车端还独立限制履带速度为 40。
- 车端启动时若存在 `/cloud.json` 和 `/wifi.json`，进入 `/app/cloud_main.py`；否则沿用局域网或原厂遥控的启动路径。配置中的口令及私有密钥不得写入仓库或终端日志。

腾讯云保留切换前的应用备份 `/var/backups/cyberbrick-real-0V1C5ko9/`；当前实车服务由 `cyberbrick-cloud-demo` 及其 systemd drop-in 启动。HTTPS 网页 IP 证书为短期证书，已配置续期定时器，但未来续期仍需观察。

## 网页打不开时

2026-11-01 在 Mac Chrome 复现过 `ERR_CONNECTION_CLOSED`：服务器 HTTPS 直连及证书正常，经当时的系统代理连接失败。为小车服务器地址添加系统代理直连例外后，Chrome 已恢复。若再次发生，分别检查服务器、直连和代理路径，勿仅凭网络错误关闭证书验证或网页鉴权。手机需核对自身网络，电脑上的代理配置不会修复手机网络。
