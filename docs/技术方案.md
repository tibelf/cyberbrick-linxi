# CyberBrick Voice — 技术方案

> 目标：用手机对 CyberBrick 小车说“前进一秒”“左转”“停”，小车照做；实体遥控器保留可用。
> 来源：基于 ChatGPT 会话《组装CyberBrick打印机》的结论整理，并补充了落地时会踩的坑。
> 状态：方案阶段，尚未写代码。

## 2. 会话方案的一个关键坑（必须先解决）

会话给的 MVP 是“手机网页用 Web Speech API → 直接 HTTP/UDP 发给 CyberBrick”。直接这么做跑不通：

| 问题 | 原因 |
|---|---|
| 麦克风权限拿不到 | 浏览器只在**安全上下文（HTTPS 或 localhost）**开放麦克风/语音识别。ESP32 上提供的 `http://192.168.4.1` 页面不是安全上下文 |
| HTTPS 页面连不上小车 | 反过来把网页放到 HTTPS 站点，再请求 `http://192.168.x.x` 会被当作混合内容拦截；浏览器网页也**不能发 UDP** |
| AP 模式下语音识别失效 | 手机连上小车热点后没有外网，而 Chrome/Safari 的语音识别大多要走云端 |

**解决：加一层“网关（Gateway）”**，让它同时做 HTTPS 网页服务和 UDP 转发。

## 3. 总体架构

```
┌──────────────┐  HTTPS + WebSocket  ┌──────────────────────┐   UDP（局域网）  ┌────────────────────┐
│ 手机浏览器     │ ──────────────────▶ │ Gateway（笔记本）      │ ──────────────▶ │ CyberBrick Core    │
│ · 麦克风按钮   │ ◀────────────────── │ · 托管网页 (mkcert)    │ ◀────────────── │ ESP32-C3 MicroPython│
│ · 方向键/急停  │   状态 / 日志        │ · 指令解析 / 动作队列   │    心跳 / 状态   │ · UDP 控制服务      │
│ · 识别结果     │                    │ · 20Hz 下发设定值       │                 │ · 看门狗自动停车     │
└──────────────┘                    │ · (v2) 云 ASR / LLM    │                 │ · 车型混控 → 电机/舵机│
                                    └──────────────────────┘                 └────────────────────┘
          三台设备连同一个网络：推荐手机个人热点（手机自带外网，语音识别可用）
```

为什么这样分层：

- **网页只负责交互**：拿麦克风、显示状态，不碰底层协议。
- **网关负责“想”**：把文本变成动作序列，按时间执行。后续接 ASR、大模型都只改这一层。
- **固件负责“做”和“保底”**：只认“当前油门/转向”这类设定值；收不到心跳就停车。即使网关或网络出问题，小车也不会一直跑下去。

## 4. 模块设计

### 4.1 固件 `firmware/`（MicroPython，运行在 CyberBrick Core）

| 子模块 | 职责 |
|---|---|
| `net` | Wi-Fi STA 连接（SSID/密码写配置文件）；连不上时回退 AP 模式，方便调试 |
| `udp_server` | 监听 UDP 端口（暂定 `6188`，和参考项目一致），非阻塞收包 |
| `protocol` | 解析/校验数据包（版本号、序号去重、范围裁剪） |
| `safety` | **看门狗**：超过 `500ms` 没收到有效包就停车；限速上限；急停锁存 |
| `mixer` | 车型抽象：`drive(throttle, steer)` → 卡车 = 电机 + 舵机；坦克 = 左右电机差速。底层调官方 `bbl.motors.MotorsController` / `bbl.servos.ServosController` |
| `led` | 状态灯：未联网 / 已联网等待 / 正在接收控制 / 急停 |
| `main` | 启动选择：**原厂遥控模式** or **语音模式** |

**与原厂遥控的共存策略**

- 原厂文件（`boot.py`、`app/`、`bbl/`、`rc_config` 等）先**完整备份到 `firmware/backup/`**，新代码只新增文件，不覆盖原厂文件。
- **MVP：模式二选一**。上电时按住某个按键（或读取配置标志）进入语音模式，否则走原厂遥控。原厂遥控大概率走 ESP-NOW，和 Wi-Fi STA 同时开要锁定同一信道，风险较高，所以第一版不追求同时工作。
- **v2：尝试注入原厂控制链路**。会话提到官方有 `rc_simulation()` 模拟遥控输入的接口（**尚未在源码中核实**）。如果属实，就把语音指令伪装成“遥控器输入”交给原厂 `control.py`，直接复用原厂的混控、舵机标定和油门曲线，同时保留实体遥控器。

### 4.2 网关 `gateway/`（Node.js + TypeScript）

| 子模块 | 职责 |
|---|---|
| HTTPS 服务 | 托管网页静态资源，证书用 `mkcert` 生成，手机安装根证书后信任 |
| WebSocket | 和网页双向通信：上行文本/按钮事件，下行状态和日志 |
| `intent`（指令解析） | v1：规则 + 关键词 + 中文数字/时长解析（“前进两秒”→ `forward 2000ms`）；v2：大模型函数调用，输出同一个 JSON Schema |
| `executor`（动作队列） | 按时间顺序执行动作序列，以 20Hz 向小车下发设定值；新指令可打断；**“停/停止/stop”最高优先级，绕过队列和大模型** |
| `device` | UDP 收发、设备发现（固件上线后广播）、心跳与延迟统计 |

选 Node/TS 的原因：网页和网关共用一套协议类型定义；`ws`、`fastify` 都很成熟。

### 4.3 网页 `web/`（Vite + React + TypeScript，移动端优先）

- 大号**按住说话**按钮（Web Speech API，`lang = zh-CN`）
- 方向键（按住移动、松开停止）+ 醒目的**急停**按钮
- 连接状态、当前动作、识别文本、指令日志
- 速度档位滑块（上限由固件兜底）
- 识别不可用时降级为纯按钮遥控

## 5. 通信协议（草案 v1）

### 5.1 网页 ⇄ 网关（WebSocket，JSON）

```jsonc
// 上行
{ "type": "voice_text", "text": "前进两秒然后左转" }
{ "type": "manual", "throttle": 0.6, "steer": 0 }     // 按钮/摇杆，按住期间持续发送
{ "type": "estop" }
// 下行
{ "type": "status", "device": "online", "rtt_ms": 18, "battery": null }
{ "type": "plan", "actions": [{ "action": "forward", "duration_ms": 2000, "speed": 0.5 }, { "action": "turn_left", "duration_ms": 500 }] }
{ "type": "log", "level": "info", "msg": "未识别：'跳个舞'，未执行" }
```

### 5.2 网关 ⇄ 固件（UDP，JSON，单包 < 200B）

```jsonc
// 网关 → 固件，20Hz
{ "v": 1, "seq": 1024, "t": 0.5, "s": -0.3, "estop": false }
//  t = throttle（油门）[-1, 1]，s = steer（转向）[-1, 1]
// 固件 → 网关，2Hz 心跳
{ "v": 1, "ack": 1024, "mode": "voice", "state": "driving" }
```

为什么流式下发设定值，而不是只发一次“前进 1000ms”：时长控制放在网关，固件就不需要维护复杂状态；**一旦断流，看门狗就会停车**，这是最可靠的失效保护。

### 5.3 动作语义（intent 输出，v1 和 v2 共用）

| action | 参数 | 说明 |
|---|---|---|
| `forward` / `backward` | `duration_ms`、`speed` | 默认 1000ms、0.5 |
| `turn_left` / `turn_right` | `duration_ms`、`speed` | 卡车 = 打舵 + 低速前进；坦克 = 原地差速 |
| `stop` | — | 立即执行，清空队列 |

安全约束：单个动作 `duration_ms ≤ 5000`，整段序列 ≤ 15s；无法识别的指令**不执行**，并在网页上提示。

## 6. 安全设计（硬性要求）

1. 固件看门狗：500ms 收不到包就停车（在固件实现，不依赖网关）
2. 急停：网页按钮 + 语音“停”，两条路径都走最高优先级
3. 速度上限：固件侧裁剪，首测限 40%
4. 首次测试时把车架起来，让车轮悬空
5. 保留物理断电方式
6. 识别结果置信度低或未匹配时，不执行任何动作

## 7. 里程碑与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 环境与备份** | Thonny/`mpremote` 连 Core，备份全部原厂文件；读懂 `app_rc` 的 `control.py`/`parser.py`，核实 `rc_simulation()` 是否存在 | 备份可以完整还原；写出原厂通道 → 电机/舵机映射表 |
| **M1 单电机实验** | REPL 里调用 `MotorsController` / `ServosController` | 能低速正反转、舵机转到指定角度 |
| **M2 固件 UDP 服务** | `net` + `udp_server` + `safety` + `mixer` | 电脑用脚本发 UDP 能控制小车；拔掉网络 0.5s 内停车 |
| **M3 网关 + 按钮网页** | HTTPS + WebSocket + 方向键/急停 | 手机网页按钮能遥控，延迟 < 150ms |
| **M4 语音 v1** | Web Speech API + 规则解析 + 动作队列 | 5 个基础指令和“前进 N 秒”识别率 ≥ 90%，“停”总能生效 |
| **M5 AI 组合指令（v2）** | 云端 ASR（解决 iOS/Android 兼容问题）+ 大模型解析成动作序列 | “前进两秒后左转再停下”能被正确拆解并执行 |
| **M6 共存（可选）** | 通过 `rc_simulation()` 或 ESP-NOW 同信道方案让实体遥控与语音并存 | 两种方式都能控制，且实体遥控优先 |

### v2 云端能力选型

- **ASR**：手机 `MediaRecorder` 录音 → 网关 → 云端 ASR，可以绕开浏览器 Web Speech API 的兼容问题
- **LLM**：网关调用兼容 OpenAI 协议的大模型接口，用 function calling 输出第 5.3 节定义的动作 JSON。项目在七牛 Hackathon 目录下，可以优先评估**七牛云 AI 大模型推理 / 语音识别服务**（具体接口和模型名待查官方文档确认）
- 两者都只改网关，固件和协议不动

## 9. 风险与待确认

| 项 | 影响 | 应对 |
|---|---|---|
| 车型未定 | 混控逻辑 | `mixer` 做成配置项，先确认车型 |
