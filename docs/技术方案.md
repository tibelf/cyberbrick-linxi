# CyberBrick Voice — 技术方案（v2：接入灵矽）

> 课题：七牛 Hackathon「智能硬件」——做一款能发子弹的小车，接入灵矽（Linx）实现语音交互。
> 目标：对小车说「往前走两秒，左转，开一炮」，小车照做并用语音回应；说「停」立刻停车。
> 状态：`linx-client/` 已实现，待实车联调。

---

## 1. 方案变更说明

v1 方案是「手机网页 Web Speech → 自建网关 → UDP → 小车」。改用灵矽后，语音识别、大模型意图理解（Function Call）和语音合成都由平台提供，v1 里的这些部分全部删掉：手机 HTTPS 证书、浏览器语音兼容、自建 ASR/LLM、规则解析。

我们手上**没有灵矽实体设备**。灵矽协议对设备开放（OTA 激活 + WebSocket + MCP），所以由电脑上的 `linx-client` 程序**模拟一台灵矽设备**。

| 项 | 结论 |
|---|---|
| 小车 | CyberBrick Mini T 类履带车 + 顶部发射器，主控 Core = ESP32-C3（MicroPython） |
| 语音/大模型 | 灵矽平台：`wss://xrobo-io.qiniuapi.com/v1/ws/`，智控台 `xrobo.qiniu.com` |
| 设备 | 软件模拟：电脑麦克风 + 扬声器 + Python 程序 |
| 控车 | v2.0：USB 串口 raw REPL（参考 CyberClaw）；v2.1：Wi-Fi UDP（无线，见 §6） |
| 参考 | [qiniu/Xrobot-docs](https://github.com/qiniu/Xrobot-docs)、[unbug/CyberClaw](https://github.com/unbug/CyberClaw)、[linx-linux 客户端示例](https://github.com/sunqirui1987/linx-linux) |

## 2. 总体架构

```
┌────────────────────────── 电脑 ──────────────────────────┐
│ 麦克风 → PCM 16k/20ms ─┐                                   │       ┌───────────────────┐
│                        ▼                                   │  WS   │ 灵矽平台           │
│                 ┌─────────────┐  hello / listen / 音频     │◀─────▶│ ASR → LLM(FC) → TTS│
│ 扬声器 ◀─ TTS ── │ linx-client │  MCP: tools/list, call    │       └───────────────────┘
│                 │  · MCP 服务  │                            │
│                 │  · 动作队列  │  ← 急停（键盘回车）          │
│                 └──────┬──────┘                            │
└────────────────────────┼───────────────────────────────────┘
                         │ USB 串口（raw REPL，每条指令一行）
                         ▼
          CyberBrick Core（ESP32-C3）：drive / aim / fire / halt + Timer 看门狗
                         ▼
          左履带 Pin2 · 右履带 Pin4/5 · 炮塔舵机 Pin3 · 发射电机 Pin6/7
```

分层：
- **灵矽负责"听和想"**：识别语音，并把「前进两秒再开火」拆成多次工具调用。
- **linx-client 负责"排程和安全"**：动作队列、时长控制、限速、发射冷却。「停」绕过队列。
- **Core 负责"做和保底"**：只执行设定值，每个动作都带看门狗定时器，到点自动停车。

## 3. 灵矽接入流程

1. **OTA 激活**：`POST https://xrobo.qiniuapi.com/v1/ota/`，携带虚拟 MAC（`Device-Id`）和 UUID（`Client-Id`）。未绑定时平台返回 6 位激活码，在智控台绑定后再次上报，即可拿到 `websocket.url` 和 `token`。
2. **WebSocket 连接**：握手请求头带 `Authorization: Bearer <token>`、`Device-Id`、`Client-Id`、`Protocol-Version: 1`。
   - 浏览器无法设置这些请求头，所以客户端只能是本地程序，不能是纯网页。
3. **hello**：上行音频声明为 PCM 16kHz/16bit/单声道/20ms，免去 Opus 编码；同时声明 `features.mcp = true`。下行格式以服务端 hello 响应为准。
4. **MCP**：平台依次发 `initialize` → `tools/list` → `tools/call`。消息格式为 `{"type":"mcp","payload":<JSON-RPC 2.0>}`。
5. **会话**：`listen start (realtime)` 后持续上传麦克风音频，收到 `stt`、`tts`、`llm` 事件。默认半双工：播报期间不上传麦克风，避免外放的声音触发指令。

智控台配置：意图识别必须选 **Function Call**，角色提示词见 `linx-client/prompts/agent-prompt.md`。工具描述还可以通过 `/v1/device/tools` 接口在云端微调，不用改代码。

## 4. MCP 工具（`linx-client/linx_client/tools.py`）

| 工具 | 参数 | 说明 |
|---|---|---|
| `self.tank.stop` | — | 立即停车并清空队列，优先级最高 |
| `self.tank.move` | `direction` forward/backward，`duration_ms` 100–5000（默认 1000），`speed` 10–100（默认 50） | 直线移动 |
| `self.tank.turn` | `direction` left/right，`duration_ms` 100–3000（默认 600），`speed` | 单侧履带转向 |
| `self.tank.aim` | `angle` 0–180 | 炮塔俯仰，90 为水平 |
| `self.tank.fire` | `shots` 1–3（默认 1） | 发射，只在用户明确要求时调用 |
| `self.tank.dance` | — | 宏动作：扭动加摇炮管 |
| `self.get_device_status` | — | 当前动作、队列、限速、已发射数 |

工具调用**立即返回「已安排」**，动作在后台队列里按顺序执行，所以大模型连续调用多个工具时会自然串成一段序列。

## 5. 安全设计（硬性要求，代码已实现）

1. **设备端看门狗**：每个 `drive`/`fire` 都会启动 `machine.Timer` 单次定时器，「时长 + 300ms」后自动调用 `halt()`。电脑死机或 USB 断开也会停车。
2. **急停有两条路**：语音「停」（`self.tank.stop`，绕过队列），或在终端直接回车。
3. **限速**：`--max-speed`（默认 40），大模型给的速度会被裁剪。
4. **时长**：单个动作 ≤ 5s，队列总时长 ≤ 15s，超出直接拒绝。
5. **发射**：单次最多 3 发，两发之间冷却 1.5s；`--no-fire` 可一键锁定；提示词禁止对人或动物开火。
6. **测试规程**：首测架空履带，发射口朝向无人区域，保留物理断电。

## 7. 风险与待确认

| 项 | 影响 | 应对 |
|---|---|---|
| 引脚映射来自 CyberClaw，未在本车验证（左履带「duty 0 = 前进」很可疑） | 方向错误 | M2 架空逐项测，改 `serial_repl.py` 的 `BOOTSTRAP` |
| 原厂程序被 raw REPL 打断 | 实体遥控暂时失效 | 退出后按复位键恢复 |
| 服务端下行可能是 opus 24kHz | 需要解码 | 安装 opuslib + libopus（代码已支持） |
| 外放回声触发误识别 | 小车自言自语 | 默认半双工；演示时用耳机或指向性麦克风 |
| 课题要求「在其内装上灵矽」 | 评委可能认为语音不在车内 | 赛前与主办方确认；备选：把同一程序放到树莓派或手机上，绑在车上 |
| 赛场网络 | 连不上平台 | 用手机热点 |
